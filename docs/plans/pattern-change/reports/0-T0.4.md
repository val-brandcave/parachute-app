## Deviations
- `skipAnimations` is also set at module load on the client (not only in an effect), because child effects run before the parent's, so an effect-only set would be one frame late.
- `celebrate` is not a hook, so it uses a non-hook twin of `useMotionMode() === "full"` (`motionOff()` + `matchMedia` reduced-motion query).
- `?motion=1` removes the sticky flag and returns false for that call only (per spec: "clears it"); it is not itself sticky.
- `useMotionMode()` reads `location`/`sessionStorage` on the client, so do not render markup that differs by mode during SSR (apply mode in effects or animation props only).
- First-load check: nothing imports `celebrate.ts` yet, so no chunk contains confetti; verified by source (dynamic import only). Re-check with a grep of `.next/static/chunks` once T1.0 wires `useArrivalCelebration`.

## Fix round 1
What changed (own files only):
1. `useMotionMode()` now uses `useSyncExternalStore(subscribeMotionMode, motionModeNow, serverMotionMode)`: server and hydration render "full" (or "off" via `NEXT_PUBLIC_MOTION=0`), then the client value applies; it also reacts to the OS reduced-motion setting changing. It no longer uses framer's `useReducedMotion`.
2. `motionOff()` is read-only. The sticky-flag write moved to `initMotionFlag()`, called once from `MotionProvider` at client module load.
3. `?motion=1` is now sticky for the tab (stored "1", honoured by `motionOff()`), as is `?motion=0`. This supersedes the earlier "?motion=1 is not sticky" deviation.
4. `motionModeNow()` in `motion.ts` is the single sanctioned `matchMedia` call, shared by `useMotionMode` and `celebrate.ts`.
5. `celebrate()` returns false and `burstFrom()` resolves quietly if the dynamic import or `confetti.create` throws; the flag stays marked.
New tests: read-only `motionOff`, sticky `?motion=1` across navigation, `motionModeNow` (off, reduced, full). `?motion=0` sticky test now goes through `initMotionFlag()`.
