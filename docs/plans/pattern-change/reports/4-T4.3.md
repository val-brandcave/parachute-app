`python app/scripts/smoke.py --flow t4_3_review_setup --base http://localhost:3403 --out app/.smoke/t4.3` (one process, light + dark, 1440 + 390): **FAIL, 8 problems, all from one cause (B2, see Requests).** Every other assertion passes in both themes:

At 390 the flow returns early (desktop-first takeover), as `t3_3` does.

The 8 failures: after Esc closes the lock dialog, the whole review closes too, in both hosts (RunModal overlay → shell, and `/reviews/[id]` → `/reviews`), so focus never gets back to Start review.

Cause: the DS Dialog (Radix `DismissableLayer`) handles Esc in a document **capture** listener and calls `preventDefault()`. React then commits the close in the microtask between listeners. By the time `RunExperience`'s document **bubble** listener runs, the dialog node is gone, so the `[role="dialog"]:not(.run)` guard finds nothing and calls `onClose()`.

Verified fix: I simulated it in a throwaway Playwright script by making document keydown listeners return early when `e.defaultPrevented`. With that, `.run` stays attached and focus lands on "Start review". `RunExperience.tsx` isn't mine, so I didn't edit it.

Screenshots reviewed (light + dark): zero-types note, address note, credits dialog over Review setup, approval dialog over Review setup (pending, dark) and the progress spoke after Run Technical only.

LockDialog was already rendered by T4.1 when the dialog assertions ran, so nothing was mocked. Its root class is `.lock-dlg` (not `.lock-dialog`); the flow selector accepts both.

Checks: `npx tsc --noEmit | grep -E "components/run/|reviews/\[id\]"` prints nothing; `npx eslint` on the 4 files is clean.
