## Deviations

- `CheckoutLauncher.tsx` also exports `checkoutBlock` and `useLaunchCheckout`. The run hosts call the launch hook directly with `returnTo=/reviews/<id>` and `types`, because `TopUpIntent` has no `returnTo`/`types` fields. The guard stays the same single rule.
- Add credits reaches the host through a React context exported from `RunConfirm.tsx`, not a new `RunExperience` prop. `RunExperience` isn't one of my files.
- `RunConfirm` reads `?types=` from `window.location` in a lazy `useState` initializer, not `useSearchParams`. The run never server-renders, and this avoids a Suspense boundary in `RunModal`.
- Seeded intake rows now open Review setup with their own `reviewTypes` (review-009 and review-011 are Technical only), per spec "else the draft's reviewTypes". Before, they opened with both types checked.
- I added the zero-balance e-mail, since none existed and the spec gives it the CTA href.
- The role-path toast is split into a title ("Only admins can buy credits") and a description ("Ask Dana.").
